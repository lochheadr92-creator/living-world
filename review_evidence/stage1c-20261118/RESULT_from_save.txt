Stage 1c, step 3: the lab from saved settlements (18 November 2026)
=====================================================================

What was built (scripts only, no rules change, rules version stays 255)
- scripts/lab_seed.ts   --load FILE (and --rules-up N, --label) starts every arm from a saved world through worldFromArgs,
                        the same loader generation_trace uses. Profile, dynamics, arrivals, rules version and settings come
                        from the save. The fork day is the save's own day. The emitted row records fromSave
                        {path, startDay, rulesUp, saveSeed}.
- scripts/lab.mjs       --saves A.save.json,B.save.json (label = file name without .save.json) runs one process per save and
                        arm on every core. --seeds --fork --profile --dynamics --arrivals --rules --geology-comparison are
                        refused beside --saves; --rules-up is refused without it. Resume compares fromSave.path, rulesUp and
                        days.
- scripts/lab_report.ts the header says "from saved settlements", names each save and its day, carries a rules-up note, and
                        states what a removal arm means from a save (see below). Mixed fresh and saved rows get a WARNING.
- tests/lab_from_save.test.ts   3 tests, all pass (see lab_from_save_test.txt).

What a removal arm means from a save (this is printed in the report)
  "A removal arm here applies from the save's day on. A saved settlement already holds what the part did before the save
  (its buildings, habits, stores and what people learned), so the arm removes the part going forward only. That reads
  differently from a removal arm in a fresh world, where the part is absent from day 0."
So a removal arm from a save measures what the part still does to a settled world. It does not measure what the part built
before the save. Results from the two modes are not to be pooled.
