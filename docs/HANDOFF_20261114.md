## How to work, learned the hard way

- Rules that add a version all edit `src/sim/rulesversion.ts`, `scripts/lab/lab.ts` and `docs/RULES_RANGES.md`: one such task
  at a time. Anything else that writes runs in its own scratch worktree and hands back a patch; the orchestrator applies and
  commits.
- A scratch worktree gets `node_modules` by a junction made from PowerShell, and the junction is removed non-recursively
  (`[System.IO.Directory]::Delete(path, $false)`) before `git worktree remove --force`. Removing it recursively deletes the
  real `node_modules`.
- Never add or change files under `src` or `scripts` in a checkout while a lab runs from it: the lab hashes them.
- PowerShell variables are not case-sensitive: `$S` and `$s` are one variable. A launch on 14 November pointed five runs at the
  wrong folders that way.
- Run measuring scripts with `node scripts/fast.mjs <script.ts> -- ...` (a quarter quicker); the pin recorders still use
  vite-node.
- Idle clean checkouts under `C:\dev\_claude_scratch\r237\` (`pin`, `pin238` to `pin242`) can be removed when convenient, each
  with the junction removed first. `pin244` only after the twenty-year runs end.
